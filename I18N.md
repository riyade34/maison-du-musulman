# Site bilingue FR / EN — mode d’emploi

Le site est publié en **français (langue principale, URLs inchangées)** et en **anglais sous `/en/`**.
Tout appartient au projet : aucun service de traduction, aucun abonnement, aucun script tiers.

## Comment ça marche

| Élément | Français | Anglais |
|---|---|---|
| Pages | `public/*.html` (source de vérité) | `public/en/*.html` **générées** |
| Textes fixes des pages | écrits dans les pages | `i18n/en-segments.json` (« texte français » → « texte anglais ») |
| Textes produits par JavaScript | valeur par défaut de `I18N.t('clé', 'texte français')` | `public/i18n-en.js` (chargé seulement sous `/en/`) |
| Produits | champs français de `public/catalog.js` | bloc `i18n.en` de chaque produit |
| Sélecteur FR \| EN, prix, adresses | `public/i18n.js` + `public/lang-switch.css` | idem |

Les pages `/en/…` sont du HTML statique complet (indexable, sans JavaScript pour lire le contenu).
`npm run i18n` les régénère depuis les pages françaises ; `npm test` échoue si elles sont obsolètes ou s’il manque une traduction.

## URLs

* Français : `/`, `/boutique.html`, `/categorie.html?cat=priere`, `/produit.html?id=chapelet`…
* Anglais : `/en/`, `/en/boutique.html`, `/en/categorie.html?cat=priere`, `/en/produit.html?id=chapelet`…

Le nom du fichier est le même dans les deux langues : le sélecteur trouve toujours la page équivalente.

## Modifier un texte de page

1. Modifier le texte français dans `public/<page>.html`.
2. `npm run i18n` liste la traduction manquante (le texte français qui n’existe plus dans `i18n/en-segments.json` est signalé, l’ancien est « inutilisé »).
3. Dans `i18n/en-segments.json`, remplacer/ajouter la ligne `"texte français": "English text"` (garder les balises HTML et les `⟦svgN⟧` identiques).
   Un même mot au sens différent : `"page.html::Texte": "…"` prime sur l’entrée générale.
4. `npm run i18n`, puis `npm test`.

## Ajouter une page

1. Créer `public/ma-page.html` avec le sélecteur de langue (copier le bloc `<!--lang-switch-->…<!--/lang-switch-->` d’une page du même type, `<link rel="stylesheet" href="/lang-switch.css">` et `<script src="/i18n.js"></script>` dans le `<head>`, et pour une page publique les 3 `<link rel="alternate" hreflang>` + `og:locale:alternate`).
2. L’ajouter à `PAGES` dans `scripts/build-i18n.js` (et à `SITEMAP_PATHS` si elle doit figurer au sitemap).
3. Compléter `i18n/en-segments.json`, lancer `npm run i18n` puis `npm test`.

## Ajouter un produit (français ET anglais)

Dans `public/catalog.js`, copier un bloc produit. Les champs français restent la référence (nom, description, prix…).
Ajouter dans le même bloc :

```js
i18n: {
  en: {
    categoryLabel: "Wellbeing",
    badge: "Handcrafted",
    name: "Nigella soap",
    tagline: "Natural cold-process soap",
    description: "Handcrafted soap enriched with nigella oil…",
    variantLabel: "Format",                       // null s’il n’y a pas de choix
    variants: { "unique": ["Single bar", "Single bar"], "lot3": ["Pack of 3", "Pack of 3"] },
    info: [["Process", "Cold-process saponification"], ["Delivery", "2–4 working days"]]
  }
}
```

`variants` est indexé par le champ `variant` français ; chaque valeur = `[libellé court du bouton, libellé complet]`.
Ne jamais traduire `variant`, `label` ni `price` : le panier, le serveur (`api/_cart.js`) et Stripe s’en servent.
`npm test` vérifie que chaque produit a sa fiche anglaise complète.

## Panier, compte, paiement

* Le panier (`maison_du_musulman_cart`) stocke toujours la version française ; l’affichage suit la langue. Un même panier suit donc le visiteur d’une langue à l’autre.
* Les e-mails Supabase (confirmation, mot de passe oublié) ramènent sur `/compte.html` (adresse autorisée côté Supabase) ; la page française redirige vers `/en/compte.html` si le visiteur a choisi l’anglais.
* Les erreurs des API sont renvoyées en français et traduites à l’affichage (`errors` dans `public/i18n-en.js`). Toute nouvelle erreur visible par le client doit y être ajoutée (un test le vérifie).
* Stripe Checkout, les e-mails de rétractation (Resend) et les noms envoyés à Stripe restent en français : non modifié volontairement avant l’ouverture de la boutique. Le retour de paiement arrive sur les pages françaises et bascule vers l’anglais grâce au choix mémorisé (`rememberLanguage`, appelé au lancement du paiement).

## Choix de langue du visiteur

* Français par défaut, jamais de détection par IP ni par langue du navigateur.
* Le choix explicite (clic sur FR ou EN, ou lancement d’un paiement) est mémorisé dans le navigateur (`mdm_lang`, stockage local, aucune donnée personnelle) ; une page française ouverte ensuite redirige vers son équivalent anglais.
* Les moteurs de recherche ne mémorisent rien : ils voient chaque langue à sa propre URL.

## SEO

* Pages publiques : `<html lang>`, canonique propre à chaque langue, `hreflang` fr / en / x-default (vers le français), `og:locale` + `og:locale:alternate`.
* Pages privées (compte, panier, recherche, rétractation, confirmation) : `noindex`, ni canonique ni hreflang ; leurs versions `/en/` privées sont exclues dans `robots.txt`.
* Fiches produit et catégories (rendues en JavaScript) : canonique et hreflang recalculés par `I18N.setAlternates`.
* `public/sitemap.xml` est **généré** par `npm run i18n` (paires FR/EN avec annotations hreflang).
* Pages juridiques anglaises : traduction informative, note « la version française prévaut » ajoutée automatiquement.
